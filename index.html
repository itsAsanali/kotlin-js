      Why
      
A transpiler, not a toolchain

      
Kotlin.js is one file. It parses a subset of Kotlin with regular expressions and
        brace-matching, not a real compiler front end — that's the trade: no type checker,
        no incremental builds, no 200MB Gradle cache. Just Kotlin-shaped syntax that becomes
        JavaScript the moment the browser reads it.

    

    

      

        0 deps
        
Single file, UMD

        
Works as a plain <script>, a CommonJS require, or an ES module. No build tool required to use it or to build it.

      

      

        <script type="text/kotlin">
        
Drop-in script tag

        
Point it at inline code or an external .kt.js file. Kotlin.js scans the page on load and runs every tag it finds, in order.

      

      

        KotlinJS.transpile()
        
Programmatic API

        
Call transpile() to get plain JS text, or run() to transpile and execute in one step — useful for editors and tools.

      

      

        val · var · fun
        
The core you'd expect

        
Declarations, functions, string templates, if/when, ranges, classes, and trailing lambdas all map to their closest JS equivalent.

      

      

        < 5 kB
        
No runtime tax

        
The whole engine — parser, transformer, DOM bootstrap — is a few hundred lines. It reads in one sitting.

      

      

        ISC
        
Read the output

        
The generated JavaScript is meant to be legible, not minified — open the playground's middle pane and see exactly what runs.

      Setup
      
Three ways to add it

      
Pick whichever matches how the rest of the page is built. All three load the same file.

    

    

      
      
      
    


    

      
      
// install
npm install kotlin.js

// use in Node, or bundle for the browser
const KotlinJS = require('kotlin.js');
KotlinJS.run('println("hi from Kotlin.js")');

<script type="text/kotlin" src="app.kt.js"></script>

    

  


  

    

      Honesty
      
Where it stops

      
Kotlin.js is a text transformer, not the Kotlin/JS compiler. It's built for demos,
        prototypes, and small scripts — know these boundaries before reaching for it in
        anything larger.

    

    

      

        
Not implemented

        
    
          
  • Null-safety is not enforced statically — ?./?: work at runtime, same as optional chaining in JS.
    • 
          
  • No coroutines, no generics inference, no sealed/enum classes.
    • 
          
  • companion object, annotations, and reflection are not supported.
    • 
          
  • Deeply nested lambdas and multi-clause when patterns get regex-fragile fast.
    • 
        

      

      

        
Good fit for

        
    
          
  • Marketing pages and prototypes that want Kotlin-flavored syntax with zero build step.
    • 
          
  • Teaching demos: paste real Kotlin snippets and show what they become.
    • 
          
  • Small interactive widgets embedded in static sites.
    • 
          
  • Anywhere you'd otherwise have reached for a <script> tag of plain JS.
    •
